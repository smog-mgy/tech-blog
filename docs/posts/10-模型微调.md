# 学习笔记 10｜模型微调：把飞轮攒下的问题按主题批量归类

**日期**：2026-07-30
**标签**：AI Agent · 模型微调 · 分类器

> 上一章数据飞轮转了一阵，把 bot 没答好的问题一条条接住，攒进低置信度问题池，几千上万条堆在那里。问题攒够了，你其实很想知道一件事：用户到底最常卡在哪一类上？是物流迟迟不到、要退换货、拿不准尺码，还是发票开不出来？搞清楚这个，才好排出先补哪块知识的优先级。几万条问题一条条调大模型打标，又贵又慢；这种量大、类目固定、还要便宜要快的归类任务，该请一台微调的小分类器出马了——这一章亲手把它训出来。

---

## 一、提示词是引导，微调是改造

- **提示词**：在输入里把规则讲清楚、摆几个例子，它顺着你的话去答，**模型参数一个都没动**。临时的——这一轮给了它就听，下一轮不给就忘
- **微调**：拿一批标好的数据再训它一轮，**动的是模型参数**，相当于改了它的脑回路，让它对某一类任务变得格外敏感。长在模型身上的——训完自己记住

**微调第一原则：能用提示词就别微调。** 基座模型越强，提示词能覆盖的活越多，需要动用微调的地方反而越少。把它省下来，只留给提示词怎么调都搞不定、但又必须要做到的那点残余。

---

## 二、什么时候才轮到微调：三道坎

以主题归类为例，提示词迈不过去的三道坎：

1. **例子举不完**：类目名单写进提示词绰绰有余（十几二十个顶天），可每个类目底下的例句（few-shot）教不完——「退货」「退款」「想退了」后面还有「退钱」「不想要了」「买错了想退」，教到的永远只是零头；还有上下文窗口限制和 Lost in the Middle，模型仍不能保证归类正确
2. **方言、口语、错别字**：「俺买的那玩意儿咋还没到俺这疙瘩」问的是物流，字面上「快递」「物流」一个字没蹦；「退货」打成「退活」得先绕过错字；「催下快递，对了这个有色差还能换不」两个主题都提到，它有时只认一个、有时两次认的还不一样——同一种说法可能今天归这类、明天归那类，答案飘忽
3. **成本**：每天堆积的问题一条条喂大模型，又贵又慢，量还天天在涨

于是专门训一个小模型接这个任务：**拿标好的数据把这套固定的分类体系训练进去，让它面对见过没见过的说法都往对的类目上靠**。小模型跑得快、成本低，只是没见过你这套类目，微调补的正是这个。

---

## 三、微调是个笨办法，先算这笔账

**划算的前提：大量、重复的处理量。** 主题归类正好对上——问题成千上万往里堆、每天还在涨，到了万级处理量，分类哪怕只错 1%，也是上百条问题被归错、上百个补知识判断跟着错，微调那点前期投入才值得做。

**还有一层容易被忽略：类目得稳。** 电商客服的主题大类（物流、退换货、尺码、发票）一年到头难得改一回，训练一遍能顶很久。要是类目隔三差五翻新，训好的模型没几天就跟不上，前期投入打了水漂。

**反过来，有些输入微调也救不了**：问题本身含糊到家、类目定义彼此重叠标的时候两个都说得通、一句话前后自相矛盾——症结在数据本身没治理干净，跟模型强不强没关系，该回头修数据和类目定义，不是加练几轮能解决的。

---

## 四、微调什么：多标签主题分类器

要给飞轮数据做分类统计：把多变、模糊的用户问题归到一个或几个固定主题类目（物流、退换货、尺码、发票…）。多数问题落一个类目；「买大了想换小一号」一句话两个诉求，尺码、退换货两个标签都打——业内叫**多标签分类**。哪个类目堆得最多、最缺知识一目了然，飞轮据此排补知识优先级。

### 跟意图识别有什么不同（为什么意图识别不微调）

- **意图识别是会话维度的任务**：判的虽是当前这一句，依据却是整个会话一轮轮积累下来的语境（用户从问物流聊到要退款又绕回物流，这叫对话状态追踪）。小模型做单句分类又快又准，可不好处理跳来跳去的上下文，除非把整段历史塞进去重新设计输入，工作量超出微调能兜的范围。也可以让微调小模型先初筛、只在拿不准时升大模型（降级路）
- **主题归类是单句维度的任务**：轮不到分类器时，上游已经把「这个」消解成具体商品（第 6 章）、把口语原话标准化成 FAQ 式标准问法（第 9 章）——一条问题就是一条语义完整的独立文本，不用管它出在哪轮对话里，正好落在小模型分类的舒适区

---

## 五、分类为什么不挑最大的模型

分类和生成是两种任务：

- **编码器模型（BERT/RoBERTa 类）天生为分类长**：把整句话读进去压成一个向量，再拿这个向量对每个类目各打一个分，哪个类目过了线就挂哪个标签——我们要的正是这种**每个类目独立出分**的本事
- **生成式大模型本行是一个字一个字蹦**，让它做分类是拿生成架构「模拟」分类，绕弯、先天吃亏
- **成本账**：BERT 类个头小，训起来、跑起来都比动辄几十上百亿参数的大模型快得多，训练部署省下的资源能差好几个数量级

中文场景这一档里 **RoBERTa-wwm-ext**（哈工大讯飞联合实验室，基于 BERT，参数量一亿出头）是稳妥选择；ERNIE 3.0、MacBERT 是同类常见选择，接口用法接近随时能换。

---

## 六、用什么微调方式

- **全参微调**：所有参数跟着训练数据更新一遍，最原始最正统、效果最好。常被念叨的坏处是吃显存、模型越大越训练不动——可这台 RoBERTa 一亿出头参数，全参训一遍几个 G 显存就够，一张消费级显卡随便跑。**分类器这个体量，全参微调就是默认选择**
- **参数高效微调（PEFT）**：原模型不碰，旁边另挂一小撮新的可训练参数，只更新这一小撮，靠它逼近全参效果、显存降一大截。**LoRA** 是 PEFT 最常用的一种；**QLoRA** 更狠，把冻住的原模型压成低精度存着，让更大模型在单张消费级显卡上也训得动——那是几十亿、上百亿参数模型才需要的手段

---

## 七、微调的成败，全押在数据这一步

选什么模型、怎么训练，都建立在好数据上。数据处理四步：

### 1. 清洗

原始问题带着手机号、订单号等敏感信息，先脱敏抹掉；错别字、乱七八糟的格式、标注里的手误一并处理。没技术含量，就是耐着性子的体力活，可漏不得。

### 2. 归并术语表

同一个意思用户有一百种说法（「退货」「退款」「退钱」「想退了」），归并到同一个标准类目底下，**全系统只认这一套术语、只有一份**——这块表叫「退货」、那块表叫「退换」，各说各话，后面全流程就乱了。

每个类目配一句**边界说明**，什么算、什么不算写清楚，近邻类目靠它划开：

| 主题类目 | 什么算这一类 | 用户的说法示例 |
|-|-|-|
| 退换货 | 退货、换货、退款怎么办；**修归保修维修，退归这里** | 退货、退款、退钱、想退了、七天无理由还能退不 |
| 物流 | 货走到哪了、什么时候送到 | 快递、发货、到哪了、怎么还不动 |
| 尺码 | 大小、码数合不合适 | 大了、小了、尺码不对、偏码 |
| 发票 | 开票、抬头、报销凭证 | 开发票、发票抬头开错了、能开增值税发票吗 |
| 质量问题 | 商品本身的毛病 | 开胶、断底、破了个洞、有瑕疵 |
| 运费 | 运费谁出、运费险理赔；**管的是钱，货走到哪了归物流** | 包邮吗、退货运费谁承担、运费险怎么赔 |
| 优惠活动 | 券和活动怎么用、能不能叠 | 优惠券、满减、活动价、能叠加用吗 |
| 价保 | 买完降价了补不补差价 | 刚买就降价了、能补差价吗、保价期多久 |
| 支付 | 付款环节出的问题 | 付不了款、花呗分期、扣了两次钱 |
| 订单修改 | 下单之后改信息、取消订单 | 改地址、改电话号码、订单还能取消吗 |
| 库存补货 | 有没有货、什么时候补 | 有货吗、断码了、什么时候补货 |
| 商品信息 | 材质、功能、用法 | 什么材质、怎么洗、会不会缩水 |
| 保修维修 | 保修期限、维修换新；**修归这里，退归退换货** | 保修多久、坏了能修吗、能换新吗 |
| 账号 | 登录、绑定、账号安全 | 登录不上、忘了密码、换绑手机号 |
| 会员积分 | 会员权益、积分怎么用 | 积分怎么用、会员几级、积分能抵钱吗 |
| 评价 | 评价、晒单的规则 | 评价怎么改、追评在哪写、晒单有奖励吗 |
| 其他 | 上面都对不上的，先兜底 | —— |

### 3. 划分数据集

切成三份：训练集（平时做的练习题，参数全靠它更新）、验证集（不参与训练、训练途中摸底考试）、测试集（正式考试，训练完去测）。常见八比一比一，按类别**分层抽样**——保证每个主题类目按比例出现在三份里，别让某类全挤在训练集、验证测试里一条都没有，那样评出来的分数会被模型投机取巧。

### 4. 数据增强

标好的样本不够，让 AI 帮着扩充：同义词替换、陈述句改成「我想问一下……」的口气，一条变出好几条。**但只能扩训练集那一份**——验证集、测试集是拿来考试的，考题照练习题变出来等于考前漏题，分数就不对了。

**标注铁律：字面提到几个主题，就标几个。**「催一下我的快递，另外这东西要是有问题还能退吧」——物流、退换货都明明白白写在字面上，两个标签都打；「这鞋买大了一码」——只标尺码，别因为「可能要退换」就顺手把退换货也标上。类目之间的关联留给业务去理清，标注不揽这个活。

**标签从哪来**：三种路线——全人工（准但慢费精力）、全大模型（快但质量参差）、最常用的是折中：**大模型照术语表先预标一遍，人工再抽样把关**。飞轮里捞的是真实问题，走的就是这条路线。样本形如 `{"text": "我的快递到哪了，怎么还没动静", "labels": ["物流"]}`，一句用户原话配一组主题标签。

---

## 八、欠拟合与过拟合：效果不行，先搞数据

- **欠拟合**：学生没好好复习，练习不会、考试新题也不会——多半是模型太弱或喂的数据特征太少，撑不起任务
- **过拟合**：学生把练习册连题带答案死记硬背——原题全对、换个说法立马傻眼（记的是题、没学会方法）。多半是数据量不够或噪音太多，只好硬背，「泛化能力」无从谈起

**结论意外地一致：效果不行，先回头搞数据。** 数据量够不够、干不干净、类别合理不，这才是根本。

---

## 九、第一版为什么总翻车：数据质量排第一

头一版训出来效果多半不理想，几乎常态。最常见的两种毛病：

1. **样本不均衡**：某些类目样本太少、数量悬殊，模型见得少的那类自然学不好
2. **标签噪声**：同一种说法「买大了想退」，这批标了尺码+退换货、那批只标退换货、还有的只标尺码——三种组合，模型收到的信号自相矛盾

解决手段也是从数据下手：稀缺类目补足、数量拉平；按「字面提到几个标几个」把标乱的样本重新对齐；模型这边配正则化防死记硬背、用早停盯验证集分数一见不再涨就收手。

---

## 十、训出来的模型得验证

拿出测试集按类目一个个算：
- **精确率**：打上的标签里多少是真该打的
- **召回率**：该打的标签漏了多少
- **F1**：两者的综合
- **混淆矩阵**：每个类目配一张，该打的没打、不该打的打了，一出来就能看清

**光看分数不够，配上误判的容忍度**：有些类目归错了无伤大雅（评价），有些归错了后果严重（退换货归错会带偏补知识优先级）——容错红线得定义下。

机器算出来的分数会被表面糊弄过去，得从判错的样本里抽一批自己看，弄明白到底错在哪一类、是不是标注本身就有毛病。**评测集务必扎在自己电商场景里造**：MMLU、C-Eval 那些通用榜单测的是通用知识，替代不了这套主题归类的真实表现。

---

## 十一、训好了怎么用：挂在旁路批量跑

分类器挂在旁路上，不参与实时对话主链路（避免不当调、不跟主业务抢资源）：飞轮里的低置信度问题攒够一批，整批喂给分类器归一次类，归类结果喂给飞轮后台看各主题分布、更新补知识优先级——不赶实时，攒着批量跑，又稳又省。

## 十二、代码走读要点

### 一份术语表，全系统只此一份

```text
ch10 权威归并术语表:全系统唯一一份,17 类主题类目。
数据处理、预标、训练、推理、评测、前端全部 import 这里,不许各自抄一份。
类目名与边界说明采用课程 README 归并术语表原文;元组顺序即 label id,训练/推理共用。
severity 是容错档位:归错会带偏补知识优先级的类目从严。
```

ML 流水线最常见也最难查的 bug：标签表在几个地方各抄一份、label id 对不上——训练时「退换货」是 0、推理时是 3，**模型没错、代码没报错，出来的结论全是错的**。

- **TopicClass** 带四样：name/boundary（近邻类目靠它划开——没有它，两个人标出两套结果、预标模型在边界上永远学不明白）/examples/severity（容错档位：归错「退换货」从严、归错「评价」可宽）
- **派生常量全部由元组推导，一个字不手写**：`LABEL2ID`、`ID2LABEL`、`NUM_CLASSES`、`SEVERITY` 全是 `enumerate` 出来的——手写一份映射表，等于给「改了类目忘了改映射」留坑，这坑不报错、只让预测悄悄错位
- `terminology_table()` 把类目定义拼成 prompt 文本——预标/造数 prompt 与代码里的定义永远是同一份，手抄一份进 prompt，改了 boundary 忘改 prompt，标注标准就跟代码对不上

### 造数据

语料从低置信池捞真实问题（带口语、错别字、方言），问题是量不够、分布很偏（物流退换货一大把，发票价保可能一条没有），接一步**模拟补足**：按类目计数、缺多少补多少（多诉求句子给命中的每一类都记一次），补到每类 100 条。最后导出抽审——真实池全量 + 每类模拟抽 5 条，**抽样固定随机种子**（重跑抽到同一批，人审过的结论才对得上）。

### 预标：四铁律

```text
1. 字面提到几个诉求就打几个标签,一个不多一个不少(「买大了想退」→ 尺码+退换货;
   「这鞋买大了一码」→ 只标尺码,不许脑补退换货)
2. 近邻边界:修归保修维修、退归退换货;运费管钱、物流管货;价保是补差价、优惠活动是券和满减
3. 方言、口语、错别字要看穿字面认诉求(「俺买的那玩意儿咋还没到俺这疙瘩」是物流;「退活」是「退货」)
4. 都对不上就标「其他」;标签必须取术语表的类目名原文
```

- 第一条治模型最爱犯的毛病：**脑补**。「这鞋买大了一码」顺手加退换货，理由是「买大了多半要退」——放客服场景很合理，放标注里就是给数据掺假，训出来的模型会把尺码和退换货绑死
- **失败兜底标「其他」但要打印出来**：不打印的话，上游抖动一批、一批样本悄悄变「其他」，语料被污染没人知道，后面看到「其他」类特别大还以为是数据本身的分布
- `lb in LABEL2ID` 过滤：模型给的标签名可能不在术语表里——schema 约束不了它编一个近似的类目名出来（跟第 5 章意图分类器同一件事）

### 划分：分层按「标签组合」

多标签分层比单标签麻烦，分层的单位是**标签组合**而不是单个标签（「退换货+运费」和「退换货」是两个不同的层）。组合种类多、有些总共三五条，全按组合分层的话某个小组合在验证集一条没有——样本少于 10 条的组合并进「它的最小 label id 那个标签的单标签层」，跟着大部队分；层内不到 3 条的全给训练集（验证集放一条孤样本没统计意义）。**seed 固定死**：划分不可复现，今天 0.86 明天 0.84，分不清是改动生效还是划分抖了。

### 增强只扩训练集（数据泄漏是「最坏的一种 bug」）

```text
增强只扩训练集——验证/测试是考题,不许照练习题变。
```

**先增强再划分**的话，同一句话的原句和变体会被分到训练集和测试集两边——模型训练时见过那句话的孪生兄弟，测试分数虚高，线上一跑就现原形，还完全不知道为什么。这类 bug 的特点：**不报错、分数还好看**。改写失败就丢掉变体不重试不拿原句凑数（拿原句凑数等于塞重复样本，模型在那一条上过拟合）。

**定向补数只进训练集**：第一版评估翻车（尺码类召回差——训练集的尺码样本都带着商品名或「尺码」字眼，真实用户说「买大了想退」这种光杆短句模型没见过），补数据时尤其容易顺手把测试集也补了（难题摆在眼前，补上去分数立刻好看）——补完测试集必须还是原来那份，分数才有可比性。

### 多标签怎么训

```python
vec = [0.0] * NUM_CLASSES     # float 向量:BCEWithLogitsLoss 要求
for lb in s["labels"]:
    vec[LABEL2ID[lb]] = 1.0
```

- 标签不是一个 id，是一个 17 维的 0/1 向量；`vec` 用浮点不用整数（BCEWithLogitsLoss 要求标签和 logits 同为浮点，填整数报的类型错误不好读）
- `problem_type="multi_label_classification"` 让 HF 自动换 BCEWithLogitsLoss——不指定默认按多分类走 CrossEntropyLoss，那个损失假设标签互斥，训出来每条只会给一个类
- 评估也得按多标签口径：sigmoid 后逐位比阈值，不是 softmax 取 argmax；micro 和 macro 两个 F1 都算——前者看整体、后者看小类目有没有被淹没

### BestInMemory：最优权重快照进内存

标准做法 `load_best_model_at_end=True` 让 Trainer 每 epoch 存一份 checkpoint，问题：**存 checkpoint 峰值要 2-3 份权重空间**（写新的时旧的还没删），本机磁盘只剩几百 MB 实测撞满两次。改成 `save_strategy="no"` 一份不存，`on_evaluate` 时把更优的 state_dict 复制到 CPU 内存，训练完回填只落一次盘。

`.to("cpu", copy=True)` 的 **copy=True 不能省**：不复制拿到的是同一块显存/内存的引用，下一步训练一更新参数，这份「最优权重」跟着变，等于什么都没存。

### 阈值也在这里定

多标签判定阈值不该拍 0.5（最优阈值跟类别不平衡、训练轮数都有关）：训完在验证集上扫一遍（0.30~0.71 步进 0.05）取 micro-F1 最高的那条线，**阈值跟模型一起存文件**——导出、服务、评测三处都读这份，不各自写死一个数。跟第 9 章置信度阈值校准同一套方法论：阈值靠数据定、定完存下来、全链路读同一份。

### 导出与上线：ONNX 轻运行时

推理只需要跑图和分词，不需要自动求导、优化器、CUDA——导成 ONNX 后依赖从 torch+transformers 缩到 onnxruntime+tokenizers，镜像和常驻内存小一大截。

- HF 模型返回 ModelOutput dict，ONNX 只认张量，包一层把 `.logits` 取出来
- **`dynamic_axes` 把 batch 和序列长度声明成动态**：不声明，导出的图只吃导出时那个样本的形状，线上来一条长度不同的句子就报错
- `dynamo=False` 是版本适配：新版 torch 默认走 dynamo 路线、导 HF 模型问题不少，显式退回 TorchScript 导出器加 dynamic_axes 这条稳定路线

### 参照模型必须重新加载（这个坑最骗人）

```python
# 一致性校验:测试集全量,ONNX 与 torch 的过线标签必须完全一致。
# 参照模型必须重新加载:tracing 会把 transformers v5 masking_utils 的分支
# 打成常量、污染进程内已有模型(实测被污染的参照 logits 差到 1.88,而文件本身没问题)
ref = AutoModelForSequenceClassification.from_pretrained(MODEL_DIR)
```

导出过程会对模型做 tracing，把 transformers 内部依赖输入的分支按当次取值打成常量，**副作用是进程内那个模型对象被改坏了**——接着拿它当对照组比对 ONNX 输出，logits 差出 1.88，得出「ONNX 导错了」的结论，实际导出的文件完全没问题，坏的是手里的对照组。解法是重新 from_pretrained 一个干净的参照模型。**这类 bug 的欺骗性：所有证据都指向被冤枉的那一方。**

校验判据是**「过线标签完全一致」不是 logits 逐位相等**——浮点运算在两套运行时之间必然有微小差异，allclose 给了容差，但业务结论不能变：同一条输入两边打出来的标签集合必须一模一样。**失败也写报告**：验收页上「上次导出没过，3 条不一致」远比一片空白有用（后者分不清是没跑过还是跑挂了）。

### apply_threshold：行为不许分叉

```python
def apply_threshold(probs, threshold):
    """sigmoid 概率 → 0/1 多标签矩阵:过线即命中;某行全不过线取最高分兜底,不产出空标签。"""
    preds = (probs >= threshold).astype(int)
    for r in range(len(preds)):
        if preds[r].sum() == 0:
            preds[r][probs[r].argmax()] = 1
    return preds
```

十六行的一个文件，两个理由让它值得单独存在：**评测和服务必须共用**（这两行决定「概率怎么变成标签」，两边各写一份，评测的 F1 就不代表线上真实表现——最典型是评测很好但线上一堆空结果）；**依赖要轻**（服务运行时没有 torch，只依赖 numpy 才能安全 import）。空标签兜底是业务判断：全不过线时给最高分那个——分类器交出空结果，这条问题在下游统计里凭空消失，「其他」类目本来就是为这种情况准备的。

serve 一次给标签 + 全部类目分数（分数给阈值扫描和验收页用，只返回标签的话没法在同一份打分上比较不同阈值）。

### 阈值扫描重演

训练时扫过一次，再用线上服务重演一遍（教学演示：让学员看见「阈值是选出来的」，而不是接受从天而降的数字）。**「打分一次、分数表固定」是关键设计**：九个候选线套同一份打分结果、只是过线位置不同——每个阈值都重新调服务的话，模型推理的不确定性会混进比较，谁高谁低说不准。打平时保留先到的（更低的阈值），这个选择可商榷但**明确写下来了**（`>` 和 `>=` 一字之差，重演结果就跟训练时选的不是同一条线）。报告带 `consistent` 字段明确回答「重演选出的线跟在用的是不是同一条」——整条链可复算的实证。

## 十三、实战要点

功能需求六条：① 数据处理四步（清洗脱敏修错别字、归并术语表 17 类每类一句边界说明、80/10/10 分层抽样、数据增强只扩训练集）；② 标注多标签字面提到几个标几个，大模型预标 + 人工抽审折中路线；③ 训练 RoBERTa-wwm-ext 全参微调不用 LoRA，验证集盯分数、正则化 + 早停防过拟合；④ 评测测试集按类目算精确率/召回率/F1 + 每类目混淆矩阵 + 人工抽判错样本复核；⑤ 部署导出推理服务挂旁路批量跑（低置信度问题攒够一批归一次类，结果写 topic_classifications 表喂飞轮后台），实时对话主链路不调它；⑥ 前端飞轮后台加主题分布页，各类目问题量做成简单图表。

验收三条：① 测试集各类目 F1 和混淆矩阵报告能跑出来；② 拿一批攒下的真实问题跑归类，后台主题分布页能看到各类目统计；③ 「买大了想退」这类多诉求句子能同时命中多个类目。

技术栈：哈工大讯飞 RoBERTa-wwm-ext 全参微调、推理服务化（ONNX）。本章不做：LoRA/QLoRA（大模型才用的手段）、embedding 微调、意图识别微调。

## 十四、本章小结

- **提示词 vs 微调**：引导（临时）vs 改造（长在身上）；能用提示词就别微调
- **什么时候上**：例子举不完 + 方言口语错别字 + 海量成本；前提是量大、重复、类目稳
- **分类不挑大模型**：编码器天生做分类（每类目独立出分），RoBERTa-wwm-ext 一亿出头全参微调就够
- **成败全押数据**：清洗 → 归并术语表（唯一一份、边界说明划近邻）→ 分层划分（按标签组合、固定 seed）→ 增强只扩训练集（防数据泄漏）
- **标注铁律**：字面提到几个标几个，不许脑补
- **效果不行先搞数据**：样本不均衡、标签噪声是第一版翻车主因
- **训练细节**：多标签 BCE 浮点向量、BestInMemory 零磁盘快照（copy=True 不能省）、阈值扫描存文件全链路读同一份
- **上线验证**：ONNX 动态轴、参照模型重新加载（tracing 污染坑）、过线标签一致为判据、评测与服务共用同一套阈值逻辑、挂旁路批量跑

到这里，从一份 17 类术语表到一个跑在独立端口上的分类服务，一条完整 ML 流水线走完。它产出的类目统计接回第 9 章数据飞轮，告诉我们哪类问题堆得最多、最该优先补知识。
