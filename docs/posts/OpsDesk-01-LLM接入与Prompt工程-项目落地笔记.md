# 第 01 章：LLM 接入与 Prompt 工程 —— 项目落地笔记

**日期**：2026-08-11
**标签**：AI Agent · OpsDesk · 项目落地笔记


> 涉及源码：`app/core/llm.py`、`app/core/prompts.py`、`app/config.py`、`app/core/model_guard.py`

## 这一章我搭了什么

把"跟大模型对话"这条通路打通。做了一个**模型工厂**（`get_chat_model()`，所有地方要模型都从这里拿），把三个**系统 Prompt** 收进一个文件集中管理，再加了一道**模型守卫**（确认上游实际在跑哪个模型）。

核心思路一句话：模型只是一个跑在远端的 HTTP 服务，POST 一段 JSON 过去、回一段 JSON 过来。整场对话就是 `messages` 数组，每条消息带角色（system 定规矩 / user 说话 / assistant 回话），而且**它是无状态的**——服务器不记你的对话，多轮记忆得自己管（后面上下文管理章解决）。

## 遇到的问题

### 1. 流式输出时 token 用量被放大了 20 多倍

**现象**：ch09 做成本统计时发现 token 数虚高一个量级；同时对话链的 token 预算闸第一步就跳闸，工具从来没执行过。

**排查**：有些 OpenAI 兼容通道在**每个流式 chunk 上都重报一遍累计用量**，而 LangChain 默认把各 chunk 的用量**相加**。两个行为叠一起：一次调用 24 个 chunk、input 恒为 11，聚合出来却是 264。

**解决**：写了一个 `_CumulativeUsageChatOpenAI` 子类，在 chunk 转换入口把累计值**换成增量**再交给上游，加完正好等于最后一个 chunk 的累计值；还加了自愈逻辑（任一项变小 = 新一条流开始，基准清零），兼容"同一实例被复用"的场景。

**教训**：库给的默认行为不等于对的。这种问题不跑真实链路根本发现不了，所以数据要早接、指标要早看。

### 2. 模型会乱承诺、会编造

**现象**：让模型自由发挥时，它会承诺"15 分钟到场""我帮您转交处理"，还会编出不存在的工单号、设备信息。运维场景这种回答是要出事的（违约纠纷、误导现场处置）。

**解决**：在系统 Prompt 里把边界一条条写死（`CUSTOMER_SERVICE_SYSTEM` 的行为约束）：

- 不臆造任何工单、设备、故障信息，查不到就明说
- 不声称会替用户转交/上报（系统没这能力，承诺了就是谎言）
- 不承诺无法保证的时效，统一表述为"以运维服务制度为准"
- 用户情绪激动先安抚再处理

**教训**：**Prompt 不是写漂亮话，是给模型立边界。**每一条约束都对应一个真实翻车场景。

### 3. 模型提取不到字段时爱传占位文本

**现象**：结构化提取时，原文里没有工单号，模型传了个 `"null"` 字符串，下游 JSON Schema 校验直接炸。

**解决**：两个层面。先在 Prompt 里堵源头（`EXTRACT_SYSTEM` 明确写"千万不要传入字符串 'null' 或 '无' 这类占位文本，直接省略参数"），再靠 JSON Schema 校验兜底。

**教训**：模型的行为怪癖，优先在 Prompt 里约束，代码兜底是第二道防线。

### 4. 模型名写错就报 Model does not exist

**现象**：同一个 DeepSeek V4 Flash，在硅基流动叫 `deepseek-ai/DeepSeek-V4-Flash`，在 DeepSeek 官方叫 `deepseek-v4-flash`，写错直接报错。

**解决**：把 base_url / model / api_key 全放 `.env`，换上游只改配置不改代码。选型时认准 **OpenAI 协议**（各家都兼容的"普通话"），换一家只是换钥匙。

### 5. 中转端点不校验模型名

**现象**：有些中转服务你传什么模型名它都用自己默认的模型应答——你以为在用 A，实际跑的是 B。

**解决**：加一道 `model_guard`，启动/调用时确认上游实际在跑的模型型号，和配置对不上就告警。

## 学到的一课

- **协议层面**：Chat Completions 无状态、OpenAI 协议是事实标准，接上游先看它认不认协议、模型名要对着上游文档写
- **工程层面**：模型调用要收口（工厂函数），配置要外置（.env），话术要集中（prompts.py），不然改一处漏三处
- **可靠性层面**：给模型的每一条约束都要有真实事故背书；流式场景下 token 计量的正确性直接影响成本统计和预算闸
