    大模型提示词工程应用学习笔记¶

    主题：提示工程的核心方法与实操 —— 从"提示工程指南"到"金融行业三大实战任务"

    前置：这篇是 Prompt 系列的应用实战篇。第一部分讲提示工程的通用方法论（指南），第二部分用金融领域三个真实任务（分类/抽取/匹配）把方法论落地——重点掌握 Prompt 的书写方式。

    第一部分：大模型提示工程指南¶

    一、什么是提示工程¶

    提示工程（Prompt Engineering）= 通过精心设计的提示技术来引导 LLM 行为，而无需更改模型权重。

    • 目标：使模型输出与给定任务的人类意图一致
    • 帮助用户控制语言模型输出，生成适合特定需求的内容
    • 注意：提示调整对确切措辞和设计很敏感 → 需要精心制定的准则

    一句话：不改模型，靠"说话技巧"让模型听你的。

    二、提示工程的两大原则¶

    原则 含义
    ① 给模型清晰指令 Prompt 要清晰明确表达需求、提供充足上下文；过于简略的 Prompt 让模型难以把握任务
    ② 让模型充足思考 像人类解题一样，匆忙得出的结论多有失误；Prompt 应加入逐步推理要求，留出思考时间

    2.1 原则一：清晰的指令（四个技巧）¶

    ① 分隔符：分隔符像 Prompt 中的"墙"，把指令、上下文、输入隔开，避免混淆

    # 用 ``` 作为分隔符：指令与待处理文本分开
text = """您应该提供尽可能清晰、具体的指示，以表达您希望模型执行的任务。"""
prompt = f"""把用三个反引号括起来的文本总结成一句话。```{text}```"""

    常用分隔符：```、"""、< >、<tag> </tag>、:，只要明确起到隔断作用即可。

    ② 结构化输出：要求模型按某种格式输出（JSON、HTML 等），方便代码解析

    prompt = f"""请生成包括书名、作者和类别的虚构的、非真实存在的中文书籍清单，
并以 JSON 格式提供，其中包含以下键：book_id、title、author、genre。"""
# 输出示例：[{"book_id": 1, "title": "幻境之夜", "author": "李梦飞", "genre": "奇幻小说"}]

    ③ 参考示例（Few-shot）：给一两个已完成的样例，"预热"模型，让它了解要求和输出样式

    prompt = f"""您的任务是以一致的风格回答问题。
<孩子>: 请教我何为耐心。
<祖父母>: 挖出最深峡谷的河流源于一处不起眼的泉眼；最宏伟的交响乐从单一的音符开始。
<孩子>: 请教我何为韧性。"""

    ④ 角色扮演：让模型充当一个角色，回答更专业明确

    我需要你充当一个AI算法面试官的角色，自主地对我进行AI面试中常考的面试题，
一次说一个问题，我回答完你再出第二道题。

    2.2 原则二：让模型思考（两个技巧）¶

    ① 指定步骤：把复杂任务拆成一步步做，要求按指定格式输出

    text = "在一个迷人的村庄里，兄妹杰克和吉尔出发去一个山顶井里打水……"
prompt = f"""1-用一句话概括下面用<>括起来的文本。2-将摘要翻译成英语。3-在英语摘要中列出每个名称。4-输出一个 JSON 对象，其中包含以下键：English_summary、num_names。
请使用以下格式：
文本：<要总结的文本>
摘要：<摘要>
翻译：<摘要的翻译>
名称：<英语摘要中的名称列表>
输出 JSON：<带有 English_summary 和 num_names 的 JSON>
Text: <{text}>"""

    ② 指导模型求解：先让模型自己解决问题，再对比学生解法判断对错——比直接判断更准

    prompt = f"""请判断学生的解决方案是否正确，请通过如下步骤解决这个问题：
步骤：首先，自己解决问题。然后将您的解决方案与学生的解决方案进行比较，
对比计算得到的总费用与学生计算的总费用是否一致，并评估学生的解决方案是否正确。
在自己完成问题之前，请勿决定学生的解决方案是否正确。……"""

    为什么有效：直接让模型判断，它会"偷懒"顺着学生思路走；让它先自己算一遍，才能发现"维护费用 100x 应为 10x"这种错误。

    三、迭代优化（Prompt 不是一次写成的）¶

    基本步骤：

    初步想法（编写初版 Prompt，清晰明确）
→ 输入模型（给模型充足思考时间）
→ 结果检查（分析 Prompt 做出改进）
→ 循环迭代（得到适合应用的 Prompt）

    案例：产品说明书 → 营销文案（三次迭代）

    迭代 问题 解决方案
    初版 生成文本太长 加长度限制："使用最多50个词"
    第1次 目标受众错（是家具零售商不是消费者），技术细节少 明确受众："该描述面向家具零售商，应具有技术性质，侧重于材料构造"
    第2次 需要更结构化 加表格要求 + HTML 格式："包括一个表格提供产品尺寸……格式化为可用于网站的HTML"

    结论：第一版 Prompt 满足"清晰 + 让模型思考"两个原则即可，之后靠多轮试错逼近最优。

    四、文本概括¶

    方式 说明 Prompt 要点
    限制输出文本长度 指定最多多少字/词 "最多30个字"
    设置关键角度侧重 按业务场景侧重（物流看运输、商家看价格质量） "并且侧重在快递服务上"
    关键信息抽取（Extract） 只提取某一角度信息，过滤其他 "提取产品运输相关的信息"（用 Extract 而非 Summarize）

    例子：评论"熊猫公仔软可爱，女儿喜欢，但有点小。快递提前一天到货。"——侧重价格质量时输出"可爱的熊猫公仔，质量好但有点小，价格稍高"；如果只想保留运输信息，就要用"提取"而不是"概括"。

    第二部分：金融行业动态方向评估项目（实战）¶

    六、项目背景与任务¶

    背景：金融领域数据大量激增，如何从繁杂数据中获取有效信息，帮助投资者减少决策失误损失，是金融数据分析的热门话题。

    AI 在金融行业的应用：风险评估（识别风险事件、反欺诈）、投资决策（分析历史数据与财报）、客户服务（智能客服）。

    传统应用 vs 大模型应用：

    传统方式 大模型方式
    门槛 需要 NLP/CV/机器学习专业知识 + 专业算法人员训练模型 不需要特别专业算法知识
    关键 分析数据、训练模型 设计合理的 Prompt 挖掘大模型的涌现能力

    项目三大任务：

    任务 业务场景
    金融文本分类 识别和评估不同类型的风险（信用风险、市场风险、操作风险等）
    金融信息抽取 自动识别提取关键信息（实体名称、日期、金额等）
    金融文本匹配 信息检索和过滤，匹配相关金融信息文本

    方法：Qwen 模型 + In-context Learning（Few-shot / Zero-shot 设计 Prompt）

    七、Few-shot / Zero-shot 思想回顾¶

    Zero-shot（零样本）：训练时没见过新类别，但模型用已有知识推广到新类别上。

    经典例子：小明认识马、老虎、熊猫后，爸爸描述"斑马有马的轮廓、老虎的条纹、熊猫的黑白"，小明就能认出从没见过的斑马。

    Few-shot（少样本）：学会大量类别后，对新类别只需要少量样本就能快速学习（让机器学会"学习"）。

    核心：用大模型学会事物异同，然后根据 support set（带标签的小样本）识别 query，即使训练集里没有这个类别。

    八、项目环境配置¶

    依赖包：rich、ollama
模型下载：ollama run qwen2.5:7b   （约 4.7GB，确保磁盘空间充足）

    本机已验证：qwen2.5:7b 已安装（4.7GB）。如果显存紧张可以换小模型（如 qwen2:1.5b），效果会略降。

    九、任务一：金融文本分类¶

    任务目标：判断一句话属于 ['新闻报道', '公司公告', '财务公告', '分析师报告'] 中哪一类。

    Prompt 设计要点： 1. 向模型解释什么叫作「文本分类任务」 2. 让模型按照指定格式输出 3. 用 In-context Learning：先给几个正确例子（User 是输入、Bot 是人工标注的期望回答）

    完整代码（finance_classify.py）：

    # -*- coding:utf-8 -*-
"""
利用 LLM 进行文本分类任务。
"""
from rich import print
from rich.console import Console
import ollama

# 提供所有类别以及每个类别下的样例
class_examples = {
    '新闻报道': '今日，股市经历了一轮震荡，受到宏观经济数据和全球贸易紧张局势的影响。投资者密切关注美联储可能的政策调整，以适应市场的不确定性。',
    '财务报告': '本公司年度财务报告显示，去年公司实现了稳步增长的盈利，同时资产负债表呈现强劲的状况。经济环境的稳定和管理层的有效战略执行为公司的健康发展奠定了基础。',
    '公司公告': '本公司高兴地宣布成功完成最新一轮并购交易，收购了一家在人工智能领域领先的公司。这一战略举措将有助于扩大我们的业务领域，提高市场竞争力',
    '分析师报告': '最新的行业分析报告指出，科技公司的创新将成为未来增长的主要推动力。云计算、人工智能和数字化转型被认为是引领行业发展的关键因素，投资者应关注这些趋势'}


def init_prompts():
    """
    初始化前置prompt，便于模型做 incontext learning。
    """
    class_list = list(class_examples.keys())
    # 【角色设定】告诉模型它是文本分类器
    pre_history = [{"role": "system",
                    "content": f"现在你是一个文本分类器，你需要按照要求将我给你的句子分类到：{class_list}类别中。"}, ]

    # 【Few-shot 示例】每个类别给一个正确例子（user 输入 + assistant 期望答案）
    for _type, example in class_examples.items():
        pre_history.append({"role": "user", "content": f'“{example}”是 {class_list} 里的什么类别？'})
        pre_history.append({"role": "assistant", "content": _type})

    return {'class_list': class_list, 'pre_history': pre_history}


def inference(sentences: list, custom_settings: dict):
    """
    推理函数。
    Args:
        sentences (List[str]): 待推理的句子。
        custom_settings (dict): 初始设定，包含人为给定的 few-shot example。
    """
    for sentence in sentences:
        with console.status("[bold bright_green] Model Inference..."):
            sentence_with_prompt = f"“{sentence}”是 {custom_settings['class_list']} 里的什么类别？"
            # 将前置历史 + 当前问题一起发给模型
            response = ollama.chat(model='qwen2.5:7b',
                                   messages=[*custom_settings['pre_history'],
                                             {"role": 'user', "content": sentence_with_prompt}])
            response = response["message"]["content"]
        print(f'>>> [bold bright_red]sentence: {sentence}')
        print(f'>>> [bold bright_green]inference answer: {response}')


if __name__ == '__main__':
    console = Console()

    sentences = [
        "今日，央行发布公告宣布降低利率，以刺激经济增长。这一降息举措将影响贷款利率，并在未来几个季度内对金融市场产生影响。",
        "本公司宣布成功收购一家在创新科技领域领先的公司，这一战略性收购将有助于公司拓展技术能力和加速产品研发。",
        "公司资产负债表显示，公司偿债能力强劲，现金流充足，为未来投资和扩张提供了坚实的财务基础。",
        "最新的分析报告指出，可再生能源行业预计将在未来几年经历持续增长，投资者应该关注这一领域的投资机会",
    ]

    custom_settings = init_prompts()
    inference(sentences, custom_settings)

    代码结构解读： - init_prompts()：构造角色设定 + Few-shot 示例的前置对话历史 - inference()：对每句话拼上问题 prompt，连同前置历史发给 Ollama - [*pre_history, {...}]：* 是解包操作，把列表元素逐一展开作为 messages 的一部分

    十、任务二：金融信息抽取¶

    任务目标：抽取句子中的 ['日期', '股票名称', '开盘价', '收盘价', '成交量'] 关键实体，按 JSON 格式输出。

    Prompt 设计要点： 1. 向模型解释什么叫作「信息抽取任务」 2. 让模型按照指定格式（JSON）输出 3. In-context Learning 给正确例子 4. 后处理：模型输出可能带 ```json 标记，需要清洗成标准 JSON

    完整代码（finance_ie.py）：

    import json
import ollama
import re

# 定义不同实体下的具备属性（Schema）
schema = {
    '金融': ['日期', '股票名称', '开盘价', '收盘价', '成交量'],
}

IE_PATTERN = "{}\n\n提取上述句子中{}的实体，并按照JSON格式输出，上述句子中不存在的信息用['原文中未提及']来表示，多个值之间用','分隔。"

# 提供一些例子供模型参考
ie_examples = {
    '金融': [
        {
            'content': '2023-01-10，股市震荡。股票古哥-D[EOOE]美股今日开盘价100美元，一度飙升至105美元，随后回落至98美元，最终以102美元收盘，成交量达到520000。',
            'answers': {
                '日期': ['2023-01-10'],
                '股票名称': ['古哥-D[EOOE]美股'],
                '开盘价': ['100美元'],
                '收盘价': ['102美元'],
                '成交量': ['520000'],
            }
        }
    ]
}


def init_prompts():
    """
    初始化前置prompt，便于模型做 incontext learning。
    """
    ie_pre_history = [{"role": "system", "content": "你是一个信息抽取助手。"}, ]

    for _type, example_list in ie_examples.items():
        for example in example_list:
            sentence = example['content']
            properties_str = ', '.join(schema[_type])
            schema_str_list = f'“{_type}”({properties_str})'
            sentence_with_prompt = IE_PATTERN.format(sentence, schema_str_list)
            ie_pre_history.append({"role": "user", "content": f'{sentence_with_prompt}'})
            ie_pre_history.append({"role": "assistant", "content": f"{json.dumps(example['answers'], ensure_ascii=False)}"})

    return {'ie_pre_history': ie_pre_history}


def clean_response(response: str):
    """
    后处理模型输出：去掉 ```json ... ``` 包裹，解析成 JSON。
    """
    if '```json' in response:
        res = re.findall(r'```json(.*?)```', response, re.DOTALL)
        if len(res) and res[0]:
            response = res[0]
        response.replace('、', ',')
    try:
        return json.loads(response)
    except:
        return response


def inference(sentences: list, custom_settings: dict):
    """
    推理函数。
    Args:
        sentences (List[str]): 待抽取的句子。
        custom_settings (dict): 初始设定，包含人为给定的 few-shot example。
    """
    for sentence in sentences:
        cls_res = "金融"
        if cls_res not in schema:
            print(f'The type model inferenced {cls_res} which is not in schema dict, exited.')
            exit()
        properties_str = ', '.join(schema[cls_res])
        schema_str_list = f'“{cls_res}”({properties_str})'
        sentence_with_ie_prompt = IE_PATTERN.format(sentence, schema_str_list)

        response = ollama.chat(
            model="qwen2.5:7b",
            messages=[
                *custom_settings['ie_pre_history'],
                {"role": "user", "content": sentence_with_ie_prompt}
            ]
        )
        res_content = response["message"]["content"]
        ie_res = clean_response(res_content)
        print(f'>>> [bold bright_red]sentence: {sentence}')
        print(f'>>> [bold bright_green]inference answer: {ie_res}')

    sentences = [
        '2023-02-15，寓意吉祥的节日，股票佰笃[BD]美股开盘价10美元，虽然经历了波动，但最终以13美元收盘，成交量微幅增加至460,000，投资者情绪较为平稳。',

    十一、任务三：金融文本匹配¶

    任务目标：判断两个句子语义是否相似，输出 ['相似', '不相似']。

    Prompt 设计要点： 1. 向模型解释什么叫作「文本匹配任务」 2. 让模型按指定格式输出（只回答是否相似） 3. In-context Learning 给相似/不相似各几个例子

    完整代码（finance_text_matching.py）：

    # !/usr/bin/env python3
"""
利用 LLM 进行文本匹配任务。
"""
from rich import print
import ollama

# 提供相似、不相似的语义匹配例子
examples = {
    '是': [
        ('公司ABC发布了季度财报，显示盈利增长。', '财报披露，公司ABC利润上升。'),
    ],
    '不是': [
        ('黄金价格下跌，投资者抛售。', '外汇市场交易额创下新高。'),
        ('央行降息，刺激经济增长。', '新能源技术的创新。')
    ]
}


def init_prompts():
    """
    初始化前置prompt，便于模型做 incontext learning。
    """
    pre_history = [{"role": "system",
                    "content": "现在你需要帮助我完成文本匹配任务，当我给你两个句子时，你需要回答我这两句话语义是否相似。只需要回答是否相似，不要做多余的回答。"}, ]
    for key, sentence_pairs in examples.items():
        for sentence_pair in sentence_pairs:
            sentence1, sentence2 = sentence_pair
            pre_history.append({"role": "user", "content": f'句子一: {sentence1}\n句子二: {sentence2}\n上面两句话是相似的语义吗？'})
            pre_history.append({"role": "assistant", "content": key})

    return {'pre_history': pre_history}


def inference(sentence_pairs: list, custom_settings: dict):
    """
    推理函数。
    Args:
        sentence_pairs (List[str]): 待推理的句子对。
        custom_settings (dict): 初始设定，包含人为给定的 few-shot example。
    """
    for sentence_pair in sentence_pairs:
        sentence1, sentence2 = sentence_pair
        sentence_with_prompt = f'句子一: {sentence1}\n句子二: {sentence2}\n上面两句话是相似的语义吗？'
        response = ollama.chat(model="qwen2.5:7b",
                               messages=[*custom_settings["pre_history"],
                                         {"role": 'user', "content": sentence_with_prompt}])
        response = response["message"]["content"]
        print(f'>>> [bold bright_red]sentence: {sentence_pair}')
        print(f'>>> [bold bright_green]inference answer: {response}')


if __name__ == '__main__':
    sentence_pairs = [
        ('股票市场今日大涨，投资者乐观。', '持续上涨的市场让投资者感到满意。'),
        ('油价大幅下跌，能源公司面临挑战。', '未来智能城市的建设趋势愈发明显。'),
        ('利率上升，影响房地产市场。', '高利率对房地产有一定冲击。'),
    ]
    custom_settings = init_prompts()
    inference(sentence_pairs, custom_settings)

    期望输出：相似 / 不相似 / 相似（第 1 对和第 3 对语义相近，第 2 对无关）。

    结尾 · 项目总结与自测¶

    三大任务对比：

    金融文本分类 金融信息抽取 金融文本匹配
    任务本质 判断文本属于哪个类别 按 Schema 抽 JSON 实体 判断两句话是否相似
    输出格式 类别名 JSON 是/不是
    关键 Prompt 设计 角色设定 + 每类一个示例 标准模板 + Schema + JSON 要求 角色设定 + 正负示例
    额外处理 无 clean_response 清洗 JSON 无
    模型 qwen2.5:7b（本机已装） qwen2.5:7b qwen2.5:7b

    通用套路：

    ① 角色设定：system 告诉模型"你是谁、做什么任务"
② Few-shot 示例：每个输出类别/格式给一个正确例子（user + assistant 配对）
③ 任务 Prompt：把当前输入套进标准问法
④ 后处理：抽取任务清洗 JSON 输出

    自测题： 1. 提示工程的两大原则是什么？—— 清晰的指令、让模型充足思考 2. 清晰的指令构造技巧？—— 分隔符、结构化输出、参考示例、角色扮演 3. 让模型思考的技巧？—— 指定步骤、指导模型求解 4. 迭代优化的基本步骤？—— 初步想法 → 输入模型 → 结果检查 → 循环迭代 5. 文本概括的主要方式？—— 限制输出长度、设置关键角度侧重、关键信息抽取 6. 文本转换的主要方式？—— 文本翻译、语气与写作风格调整、格式转换、拼写及语法纠正 7. Zero-shot 和 Few-shot 的核心区别？—— Zero-shot 不给例子直接用知识推广；Few-shot 给少量标注样本 8. 信息抽取为什么需要 clean_response？—— 模型输出常带 ```json 包裹，需要清洗成标准 JSON 才能解析
