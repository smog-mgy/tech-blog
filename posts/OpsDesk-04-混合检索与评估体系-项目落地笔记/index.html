    OpsDesk 04｜混合检索与评估 · 项目复盘¶

    记录日期：2026-08-23 标签：AI Agent · OpsDesk · 项目落地笔记

    比较向量、关键词、融合与重排各自解决的问题，并区分仓库历史报告和当前复测。

    涉及源码：app/core/retrieval.py、app/core/rerank.py、app/core/embeddings.py、scripts/eval_retrieval.py、tests/data/eval_ch04.jsonl

    先说说这条路是怎么被逼出来的¶

    第 3 章做完基础 RAG，能答知识类问题了。但拿真问题一测就露馅：用户问「电机不转了」，库里写的是「电机过载跳闸」——字面对不上，纯向量倒是能匹配上，因为语义接近。可另一头，用户报设备型号「TS-4001」和「TS-4101」，语义几乎贴着，差一位就是另一台设备，纯向量分不开。单路检索永远有盲区：语义路不懂精确字面，字面路听不懂换说法。

    于是往检索链路上加了东西，一步一步变成现在的样子。

    纯向量这路，换说法也拦得住¶

    先有的一路是向量检索（bge-m3 嵌入）。为了验证"换个说法还能不能召回"，写了个最小评估脚本 scripts/eval_retrieval.py：拿 5 条换说法的问题（比如「响应时效是多少」期望命中"响应"），跑纯向量检索，核对召回结果的 answer 里含不含期望内容。它只测向量召回、不掺 LLM，跑一遍就知道这一路有没有退化。

    把关键词那一路请回来¶

    向量之外补了 BM25 关键词路。设备型号、工单号这种精确串，BM25 一打一个准。两路并存之后遇到第一个真问题：两路的分怎么合。BM25 的分数取决于词频和文档长度，向量分数取决于模型空间，量纲根本不可比——直接加权相加等于拍脑袋定权重，换个知识库就要重调。所以用 RRF：只认名次，1/(k+rank)，两路各自的排名合成一个排序，不碰原始分数。

    加完混合，反而掉点¶

    这是这条链路里最反直觉的一课。旧笔记曾记录纯向量 Recall@5 0.973、混合未重排 0.942；公开仓库未保留这两次运行的完整原始报告，因此这里只保留为待复核的历史对比——两路召回混进来的噪声没人筛，把原本靠前的真结果挤了下去。解决靠最后一道关：Cross-Encoder 精排（bge-reranker），把问题和每个候选拼在一起看词级交互，只对前 N 条重排（精排慢，不能全量）。仓库保留的另一份趋势记录中，Recall@5 为 0.986、MRR 为 0.897；它不能补齐上述两次对照实验。

    召回负责全、精排负责准，少一环就会互相拖累——这句话是这个月最值钱的认知。

    评估体系是怎么长出来的¶

    没有线上流量，怎么知道自己做对了？搭了四层评估，各管一段：

    1. 检索评估（离线确定性）：eval_ch04.jsonl 评估集上跑四路策略对比（纯向量/纯BM25/混合/混合+精排）的 Recall@5 和 MRR，不掺 LLM，可复现
    2. 忠实度评估：用裁判模型重放「检索证据 + 回答」，判断回答里的具体事实主张（时效、费用、设备参数）是否都能被证据支撑
    3. 拒答评估：故意问知识库里没有的问题，必须被拒答——测的是"不说胡话"
    4. 意图/分类器评估：意图稳定性 + 分类器每类 P/R/F1（第 6、10 章）

    跑完的指标落 eval_runs 表连成趋势线，确认每次改动没把质量拉下来。旧笔记记录的历史样例：Recall@5 0.986、MRR 0.897、忠实度 1.000、拒答率 0.983。

    这一路埋过的几个坑¶

    rerank 地址少个版本段。上游地址只填到域名的话，拼出来的 /rerank 会 404——而且只在查询时以"hybrid_rerank 失败"的形式冒出来，排障要绕一大圈。_rerank_url 里做了修正：地址带不带 /v1 都收，缺了就补。

    连接层抖动不重试，整轮评估白跑。早先只按状态码重试（429/5xx 重试），上游把连接掐了反而一次都不试——eval-rag 跑到第 200 多题被断一次，十几分钟整轮白跑。后来把 httpx.TransportError（断连、读超时、连不上）也纳入退避重试。限流是按秒的，退一步再试就过去；连试几次还不行才抛出去，评估脚本会把这一轮记成失败，不会静默算低分。

    中文没有词边界（第 3 章已踩），检索侧的 split_clauses 拆子句也是为中文标点写的。

    现在的检索链路长这样¶

    问题进来
 → split_clauses 拆子句（一问多意图时）
 → 每路子句跑 vector + bm25 双路召回
 → RRF 名次融合
 → bge-reranker 精排前 N 条
 → arrange_head_tail 首尾摆放（缓解 lost-in-the-middle）
 → 证据进 Prompt，模型按证据答、标来源编号

    怎么验证¶

    make smoke-rag      # Milvus + BM25 + rerank 冒烟
make eval-check     # ch04 评估集自检（ground truth 可命中 + 要点逐字可查）
make eval-rag       # 四策略评估（SKIP_GEN=1 只跑确定性两段）
make eval-retrieval # 纯向量换说法召回验证
